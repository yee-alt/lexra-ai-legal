Safety: when may it send automatically?

All six conditions must hold. Otherwise: a person.

  • Policy allows auto-reply (only 3 of 87 scenarios)
  • Risk low, info only, confidence ≥ 0.85
  • No customer case, no sensitive data, no side effect
  • Evidence approved, current, right scope, no conflict
  • Every statement has a valid citation
  • Runtime switch on (off by default)

Prompt injection

Mail and PDF are data only. The LLM has no tools. It can only raise risk, never lower it.

Failures

Low confidence, no evidence, conflict, timeout, unknown scenario: escalate, ask, or failed_safe. Never guess.

Likely questions, short answers

Why a knowledge graph?

Rules, scope, versions and sources are explicit and queryable. Vector search finds similar text but does not know which segment or version applies.

Why not vector search only?

Two pages with almost the same text (other segment, old version) look identical to vectors. Filters and claims separate them. We test this with the A to D ladder.

Why two stores?

Qdrant: pre-filters and vectors. Neo4j: relations, status, source. Linked by chunk_id. Risk: drift. So Neo4j re-checks. Atomic publishing is not built yet.

How do you contain the LLM?

No tools, fixed schema, permissions only in the backend, injection signal. The model can only raise risk.

How do claims enter the graph?

The LLM extracts in a fixed schema. The backend checks predicate, entity and literal evidence. Valid: draft claim. Unclear: needs_review. A person approves.

If Neo4j fails or there is no evidence?

Fail safe: to a person, never guess.

Is there real multi-hop?

Rarely. The value is scope, versions and provenance. We measure it rather than claim it.

Why LangGraph?

Persisted state, pause for human approval, conditional routes, resume. A fixed graph with no free agent loops.

What is missing?

See status: webhook, MongoDB, OCR, authentication, domain API, review UI, sender, eval runner, atomic publishing.
